# Pragati Track

Shipment tracking for **Pragati Logistics**: customers and the support desk see where every parcel is.

> Starter project for the **Claude Code Complete Masterclass** (Skills Pragati, free course). Pragati Logistics, its people,
> customers and shipments are fictional. Each lesson's end state is a git tag (`partNN-…`), so you can check out any point.

| Folder | What it is | Stack |
|---|---|---|
| `api/` | Shipments API on port 8000 | Python 3.12, FastAPI, Pydantic v2, pytest |
| `web/` | Control-tower dashboard and customer tracking page on port 5173 | React 18, Vite, TypeScript, Vitest |
| `legacy/rate-calc/` | Booking-desk price calculator CLI | Plain Node.js (CommonJS) |

The three folders are independent: no shared build, no root `package.json`. Every command below is run from inside
the folder it belongs to. How the pieces fit together is in [docs/architecture.md](docs/architecture.md); the support
tickets that drive the work are in [docs/support-tickets.md](docs/support-tickets.md).

## Quick start (Windows PowerShell)

### 0. Prerequisites

- **Git**
- **Python 3.12** (`python --version` should print 3.12.x)
- **Node.js 20 or newer** with npm (`node --version`)

The commands below never activate the virtual environment, so they work regardless of your PowerShell execution
policy. Every code block starts at the repo root (`pragati-track`) and does its own `cd`, so each one can be pasted
on its own.

### 1. Clone

```powershell
git clone https://github.com/mukesh-ranjan/pragati-track.git
cd pragati-track
```

### 2. API: set up and test

```powershell
cd api
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m pytest -q
```

You should see all tests pass (`12 passed` at the time of writing). The tests import `app.main`, so pytest must be run
from `api`, not from the repo root. To run one test:

```powershell
cd api
.\.venv\Scripts\python -m pytest -q tests/test_shipments.py::test_filter_by_status
```

### 3. Web: set up and test

```powershell
cd web
npm install
npm test
```

`npm test` runs Vitest once and exits. Other useful commands:

```powershell
cd web
npx vitest run src/format.test.ts     # one file
npx vitest run -t "reads like"        # one test by name
npm run build                         # type-check (tsc -b) and build to dist/
```

### 4. Run both

Use two terminals, each starting at the repo root.

**Terminal 1: API**

```powershell
cd api
.\.venv\Scripts\python -m uvicorn app.main:app --reload
```

Runs on http://localhost:8000. The interactive **API reference** (Swagger UI, generated by FastAPI) is at
<http://localhost:8000/docs>, and the health check is at <http://localhost:8000/health>.

**Terminal 2: web**

```powershell
cd web
npm run dev
```

Opens on <http://localhost:5173>. Pages:

| URL | What it shows |
|---|---|
| `/` | Control-tower dashboard (KPIs, live map, needs-attention list) |
| `/track` | Customer tracking table, filter by tracking ID (try `PRG-10021`) |
| `/shipments/PRG-10021` | One shipment's journey timeline |
| `/style-tile`, `/gallery` | Design tokens and component gallery |

The web app calls the API at `http://localhost:8000` by default. To point it elsewhere, set `VITE_API_URL` in a
`.env` file inside `web` (git-ignored). The API only allows CORS from `http://localhost:5173`, so keep the Vite port
as is.

### 5. Legacy rate calculator (optional)

No install step. From the repo root:

```powershell
cd legacy\rate-calc
node ratecalc.js Mumbai Pune 2.3 express 40x30x20
node --test
```

`node --test` runs the four `*.test.js` files with the built-in `node:test` runner. Note that `npm test` in this folder
is a stub that prints "no tests" and exits 0, so always use `node --test`.

## Checking the docs

A dependency-free script verifies that relative links in every `.md` file resolve, that every `npm run` script named
in a README exists in that folder's `package.json`, and that every file path in a README code block exists. Run it from
the repo root:

```powershell
node docs/check-docs.mjs
```

It exits non-zero with a `file:line: message` list when something is broken.

## Conventions

- Status values are a closed set shared by API and web: `booked`, `picked_up`, `in_transit`, `out_for_delivery`,
  `delivered`, `exception`. Adding one means updating `Status` in `api/app/models.py`, the `Status` type in
  `web/src/api.ts`, and the label map in `web/src/format.ts`.
- Tests and commit messages cite the support ticket ID they address (for example `T-4512`).
- Do not change the zone table in `legacy/rate-calc/zones.json` without asking Suresh.
